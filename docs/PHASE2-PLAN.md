## 2. 里程碑（按序执行，每里程碑单独 commit 组，同一 PR 或 phase2 PR）

### M1 — 真表单闭环（优先）

1. 学生：选中/新增从预览升级为可编辑表单（学号、姓名、性别、班级、手机、学籍等）；提交走 `/api/v1` 写接口；校验与失败提示。
2. 用户账号：新增/编辑/启停；初始密码仅新增；图例保持。
3. 课程与排课：班级授课 CRUD + 课程库关键字段编辑；周课表只读或按现有 API。
4. 考勤：日报汇总只读为主；异常明细可补录/更正（若 API 支持，否则标 TODO 对接资深程序员）。
5. 公告：发布/编辑/置顶/已读；范围字段对齐后端。
6. 成功标准：各页「+新增」与行内编辑可保存并刷新列表；网络失败仍用 `load-hint`；不恢复 `.page-head`。

### M2 — 组织与课表

1. 年级/班级：Framer 拆页后置项落地——`OrgClassesPage` 拆为年级页 + 班级页（或 Tab 深链），路由与侧栏 IA 更新；权限 `org:write`。
2. 我的课表：对接稳定 `fetchMyTimetable`；空态/服务不可用文案统一；教师/学生视图差若 API 有则做。
3. 成功标准：年级班级可独立维护；课表页无大标题、错误态清晰。

### M3 — 权限、角色与壳层

1. 角色权限页（若 Framer `/roles` 在二期范围）：只读矩阵或可编辑（以后端为准）。
2. 侧栏按 `ROLE_PERMISSIONS` 裁剪复核；隐藏无权限入口；`*` 勿再作为 ADMIN 权限种子。
3. 顶栏：面包屑保持「校园OA / …」；铃铛/通知若有 API 则接，否则保持 UI。
4. 成功标准：四角色冒烟（ADMIN/ACADEMIC/TEACHER/STUDENT）入口与按钮可见性正确。

### M4 — 体验与视觉收口

1. 空态、加载态、分页、筛选行与 Framer `/users` 母版再对一遍（尺寸不回 264）。
2. 表单预览区与编辑态切换动效克制；三列布局在窄屏可接受降级。
3. `docs/v1.3-shots/` 增补二期关键页截图；Token 变更记入 `tokens.css` 注释。
4. 成功标准：需求/美工可按截图抽检；无新增「差不多」尺寸漂移。
